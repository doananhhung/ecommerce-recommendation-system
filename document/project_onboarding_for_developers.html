Two-Stage Recommender System

Tài liệu onboarding cho lập trình viên mới: mục tiêu bài toán, dữ liệu, kiến trúc, luồng huấn luyện, luồng serving, các file quan trọng, cách chạy, cách kiểm thử và các điểm cần cải thiện của dự án.

1. Tổng Quan Dự Án

Dự án xây dựng hệ thống gợi ý sản phẩm thương mại điện tử theo mô hình two-stage recommender. Ý tưởng chính là không xếp hạng toàn bộ sản phẩm ngay từ đầu, vì số lượng item lớn và ma trận user-item cực kỳ thưa. Thay vào đó hệ thống chạy hai bước:

  1. Recall stage: lọc nhanh từ hàng chục nghìn hoặc hàng triệu item xuống khoảng vài trăm ứng viên.
  2. Ranking stage: chấm điểm chi tiết các ứng viên và trả về top-N sản phẩm tốt nhất.

Bài toán

Nhận user_id, trả về danh sách product_id nên gợi ý.

Dữ liệu

Log hành vi e-commerce gồm view, cart, purchase.

Model

PyTorch Matrix Factorization cho recall, LightGBM binary scorer cho ranking.

Serving

FastAPI nạp feature store, model weights, FAISS index và ranker vào bộ nhớ lúc startup.

Các vấn đề dữ liệu cốt lõi

Vấn đề Ý nghĩa Cách dự án xử lý
Mất cân bằng lớp view áp đảo cart và purchase, model dễ học cách dự đoán toàn negative. Negative sampling ở recall, Focal Loss trong PyTorch, is_unbalance=True và sample weight truyền vào LightGBM.
Ma trận user-item thưa Rất ít user tương tác với rất ít item so với toàn bộ không gian khả dụng. Dùng embedding user/item và vector search thay vì duyệt toàn bộ item.
Thiếu dữ liệu categorical brand, category_code có nhiều null, không nên thay bằng số 0 nếu dùng làm categorical. Code đã gán nhãn <UNKNOWN> và sử dụng kiểu dữ liệu category cho mô hình LightGBM tự động tối ưu.
Data leakage theo thời gian Feature hoặc split dùng thông tin tương lai sẽ làm offline metric ảo. featurizer.py tính point-in-time cumulative features. run_ranking.py đã áp dụng Time-based Split (sắp xếp theo thời gian rồi cắt) thay cho random split.

Dự án dùng uv để quản lý môi trường. Trong máy hiện tại, gọi Python qua uv run python là cách ổn định nhất.

uv sync

Chuẩn bị dữ liệu raw

Code cấu hình mặc định đọc file: data/raw/2019-Oct.csv. Thư mục hiện có cả 2019-Oct.csv và 2019-Nov.csv.

Huấn luyện end-to-end

uv run python main_train.py

Lệnh này chạy lần lượt:

uv run python -m src.data_pipeline.run_pipeline
uv run python -m src.recall_model.run_recall
uv run python -m src.ranking_model.run_ranking

3. Kiến Trúc Tổng Thể

Kiến trúc hiện tại là offline training kết hợp online serving. Offline sinh ra feature store và model artifacts. Online API chỉ nạp artifacts đã có, không train lại.

Raw Events CSV hành vi: user, product, event type, thời gian, category, brand, price.
Data Pipeline Sessionization, point-in-time features, pseudo labels, parquet stores.
Recall Training Encode user/item, negative sampling, Matrix Factorization, item embeddings.
Ranking Training Join interaction labels với user/item features, train LightGBM.
Serving FastAPI: user embedding -> FAISS top-K -> feature lookup -> LightGBM -> top-N.

Luồng training

main_train.py
  -> src.data_pipeline.run_pipeline
      -> sessionizer.create_sessions
      -> featurizer.extract_user_features
      -> featurizer.extract_item_features
      -> featurizer.add_point_in_time_features
      -> pseudo_label.apply_pseudo_labels
  -> src.recall_model.run_recall
      -> LabelEncoder user_id/product_id
      -> ImplicitFeedbackDataset
      -> MatrixFactorization
      -> RecallTrainer with FocalLoss
      -> save recall_weights.pth, item_embeddings.npy, encoders
  -> src.ranking_model.run_ranking
      -> join labeled interactions + feature snapshots
      -> train LightGBM
      -> save ranker_model.txt

Luồng inference

HTTP GET /recommend/{user_id}
  -> RecommendationPipeline.recommend(user_id)
  -> map user_id to user_idx
  -> get user embedding from recall model
  -> FAISS IndexFlatIP retrieves top-K item_idx
  -> map item_idx to product_id
  -> reindex item features and attach user features
  -> LightGBM predicts scores
  -> sort descending and return top_n recommendations

5. Data Pipeline

Pipeline nằm trong src/data_pipeline. Nhiệm vụ là biến CSV raw thành các bảng parquet phục vụ training và serving.

sessionizer.py

Hàm create_sessions(df, threshold_minutes=30) sort dữ liệu theo user_id và event_time, tính khoảng cách thời gian giữa hai event liên tiếp của cùng user, rồi tạo custom_session_id. Nếu event đầu tiên hoặc cách event trước hơn 30 phút, đó là session mới.

featurizer.py

Hàm Đầu ra Điểm quan trọng
add_point_in_time_features user_total_interactions, user_total_sessions, item_total_interactions, item_unique_users, item_avg_price Tính cumulative features chỉ dựa trên event trước dòng hiện tại, giúp giảm leakage.
extract_user_features Snapshot tổng số tương tác và số session theo user. Dùng cho feature lookup lúc serving.
extract_item_features Snapshot tổng tương tác, số user unique, giá trung bình theo item. Dùng cho LightGBM ranker.

pseudo_label.py

Gán nhãn huấn luyện từ implicit feedback:

event_type label sample_weight event_strength
view00.10
cart10.51
purchase11.02

Với mỗi nhóm custom_session_id, product_id, user_id, pipeline giữ lại event mạnh nhất và mới nhất để tạo một training row duy nhất.

run_pipeline.py

Entry point gọi lần lượt sessionization, snapshot feature extraction, point-in-time feature generation, pseudo labeling, rồi lưu parquet. Số dòng raw đọc vào được điều khiển bởi config.PIPELINE_NROWS, hiện là 1_000_000.

6. Recall Model

Recall stage dùng Matrix Factorization trong PyTorch để học embedding cho user và item. Mục tiêu là tìm nhanh các item có dot product cao với user embedding.

Thành phần code

File Vai trò
src/recall_model/dataset.py ImplicitFeedbackDataset chuyển user idx, item idx, label thành tensor.
src/recall_model/model.py MatrixFactorization gồm nn.Embedding cho user và item, score bằng dot product qua sigmoid.
src/recall_model/trainer.py FocalLoss và RecallTrainer, tự chọn CUDA nếu có.
src/recall_model/run_recall.py Đọc labeled parquet, negative sampling, label encoding, train, save artifacts.

Negative sampling

Code lấy toàn bộ positive rows (label > 0) và sample negative rows theo tỷ lệ config.RECALL_NEG_SAMPLE_RATIO. Giá trị hiện tại là 4, nghĩa là 1 positive : 4 negatives.

Loss function

FocalLoss(alpha=0.25, gamma=2.0) giảm ảnh hưởng của các mẫu dễ và tập trung hơn vào mẫu khó, phù hợp với dữ liệu implicit feedback mất cân bằng mạnh.

Artifacts sinh ra

  • models_store/recall_weights.pth: trọng số PyTorch.
  • data/feature_store/item_embeddings.npy: item embedding để build FAISS.
  • models_store/user_encoder.joblib và models_store/item_encoder.joblib: mapping ID thật sang index.
  • models_store/recall_metadata.json: số user, số item, embedding dimension.

7. Ranking Model

Ranking stage dùng LightGBM để chấm điểm ứng viên. Nó không tìm ứng viên từ toàn bộ item catalog, mà nhận danh sách candidate từ recall stage.

Feature set hiện tại

user_total_interactions
user_total_sessions
item_total_interactions
item_unique_users
item_avg_price
hour_of_day
day_of_week

Training flow

  1. Đọc labeled_sessions.parquet, user_features.parquet, item_features.parquet.
  2. Join theo user_id và product_id.
  3. Fill missing numeric features bằng 0.
  4. Chia train/test bằng train_test_split(..., random_state=42).
  5. Train lgb.train với objective binary, metric binary_logloss và auc.
  6. Đánh giá thêm NDCG@10 và MRR theo user_id.
  7. Lưu model vào models_store/ranker_model.txt.

Code chính

File Vai trò
src/ranking_model/lgbm_train.pyRankingTrainer, train/evaluate/save LightGBM. Đã cấu hình chống mất cân bằng nhãn.
src/ranking_model/metrics.pyTính NDCG@K và MRR, có hỗ trợ group theo query/user.
src/ranking_model/run_ranking.pyEntry point training ranking model. Đã cấu hình Time-based split và Imputation tự động.

8. Serving Và API

Serving nằm trong src/serving và main_serve.py. Toàn bộ model và feature store được nạp một lần trong FastAPI startup.

Startup

pipeline = RecommendationPipeline(
    models_dir=config.MODELS_DIR,
    feature_store_dir=config.FEATURE_STORE_DIR,
)
pipeline.initialize()

RecommendationPipeline.initialize() làm gì?

  1. Đọc user_features.parquet và item_features.parquet vào memory.
  2. Nạp encoder artifacts nếu có, nếu không thì rebuild mapping từ feature store.
  3. Build FAISS IndexFlatIP từ item_embeddings.npy.
  4. Nạp recall_weights.pth vào MatrixFactorization.
  5. Validate số user/item giữa mapping, FAISS và PyTorch weights.
  6. Nạp LightGBM model từ ranker_model.txt.

API endpoints

Endpoint Ý nghĩa Response
GET / Health/info đơn giản. Message hướng dẫn dùng /recommend/{user_id}.
GET /recommend/{user_id}?top_n=20 Recommend theo user ID thật. user_id, user_idx, recommendations, latency_metrics.
GET /recommend-by-index/{user_idx}?top_n=20 Recommend theo index nội bộ, hữu ích cho debug. Tương tự endpoint theo user_id.

Cold-start behavior

Nếu user chưa có trong mapping hoặc user_idx ngoài biên, pipeline trả lỗi cold-start với danh sách recommendation rỗng. Fallback phổ biến như popular items, category trending hoặc session-based recall chưa được triển khai.

12. Testing Và Debug

Smoke test hiện có

uv run python tests/smoke_test.py

Test này kiểm tra:

  • Thư mục artifacts tồn tại.
  • RecommendationPipeline.initialize() nạp được feature stores, FAISS, recall model và ranker.
  • Đọc user mẫu từ user_features.parquet.
  • Gọi pipeline.recommend(..., top_n=5).
  • Response có key recommendations và không trả quá 5 item.

Kết quả kiểm tra gần nhất

Smoke test đã chạy thành công. Với user mẫu 244951053, pipeline trả được top-5 recommendation. Tổng latency được ghi nhận khoảng 20.84 ms trong lần chạy đó.

Các lỗi thường gặp

Triệu chứng Nguyên nhân thường gặp Cách xử lý
Không import được package Chưa chạy uv sync hoặc gọi sai Python. Dùng uv run python ....

14. Mental Model Cho Người Mới

  1. Đừng bắt đầu từ model. Hãy hiểu raw event log, session, label và feature trước. Sai feature hoặc leakage sẽ làm model đúng giả.
  2. Recall là bước lấy ứng viên. Nó ưu tiên nhanh và phủ rộng, không cần xếp hạng cuối cùng thật chuẩn.
  3. Ranking là bước quyết định thứ tự. Nó dùng feature rõ ràng hơn và chỉ xử lý vài trăm ứng viên.
  4. Serving phụ thuộc chặt vào artifact consistency. Mapping user/item, embeddings, weights và feature store phải sinh từ cùng một phiên bản dữ liệu.
  5. Đánh giá recommender phải theo thời gian. Với hành vi người dùng, validation ngẫu nhiên dễ trộn tương lai vào quá khứ.

15. Checklist Khi Thêm Tính Năng

  • Nếu thêm feature mới, thêm ở data pipeline, training ranking và serving ranker cùng lúc.
  • Nếu đổi embedding dimension hoặc số user/item, train lại recall và rebuild item embeddings.
  • Nếu đổi mapping encoder, đảm bảo API dùng đúng encoder artifact từ cùng lần train.
  • Nếu đổi label logic, kiểm tra lại tỷ lệ positive/negative và metrics ranking.
  • Nếu đổi API response, cập nhật smoke test và tài liệu endpoint.
  • Nếu thêm filtering business rules, áp dụng sau recall và trước ranking hoặc sau ranking tùy yêu cầu.
